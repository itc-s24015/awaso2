# お店・駐車場検索

## 詳細
Google Maps Platformを利用し、日本国内の企画の行き先候補としてお店・飲食店・カフェまたは駐車場を検索できるようにする。検索語は自由入力とする。検索地域には利用者が入力した地域、または利用者が許可した端末の現在地を使う。検索半径は5km・10km・20km・50kmから選択し、初期値は10kmとする。検索結果は直線距離の近い順に最大10件表示する。

## 仕様
### 処理の流れ
1. 利用者が検索語、検索対象、検索半径を指定する。検索対象の初期値は「お店・飲食店・カフェ」とする。
2. 利用者は地域を入力するか、「現在地を使う」を明示的に選び、ブラウザーの位置情報利用を許可する。
3. 地域入力の場合はGoogle Geocoding APIで日本国内の検索中心座標を取得する。現在地の場合はブラウザーが許可後に返す座標を使用する。位置情報は検索処理にのみ使用し、保存しない。
4. Google Places API (New) Text Searchで検索し、結果の座標から検索中心までの直線距離を算出する。指定半径内にある結果のみを距離順に最大10件表示する。
5. 候補の名称・住所・距離を表示する。場所IDを用いてお気に入り登録できる。候補の位置座標は地図表示機能（FR-007）へ渡せるよう検索結果内だけで扱い、永続化しない。
6. 駐車場の料金・空き状況は保証しない。

### 入出力
- 入力：検索語（1〜120文字）、検索対象（お店・飲食店・カフェ／駐車場）、検索地域または現在地、検索半径（5km・10km・20km・50km）。
- 出力：最大10件の場所ID、名称、住所、検索中心からの直線距離、地図表示に使う場所座標。
- 初期値：検索対象は「お店・飲食店・カフェ」、検索半径は10km。

### 例外・制御
- 検索対象が「お店・飲食店・カフェ」の場合、Places APIの1リクエストにつき1種類の型しか指定できないため、`store`、`restaurant`、`cafe`をそれぞれ検索し、Place IDで重複を除いて統合する。駐車場の場合は`parking`を検索する。
- Text Searchの円形`locationBias`は検索結果を中心付近へ寄せる指定であり、半径外の候補も返す。そのため、座標を用いてサーバー側で半径内か判定し、半径外の候補を表示しない。
- 検索結果の場所座標は距離計算・地図表示に使う一時データとし、DBやブラウザーの永続ストレージへ保存しない。HTTP応答はキャッシュしない。
- 位置情報の許可拒否・取得失敗時は地域入力へ切り替えられるようにする。Geocodingで地域が見つからない場合や外部APIが失敗した場合は、検索失敗を利用者へ明示する。
- 地域入力のGeocoding APIは`country:JP`で日本国内に限定する。Text Searchでは日本語と日本向けの設定を指定する。
- 外部サービスの結果が指定半径内にない場合は、検索条件を変える案内を表示する。
- Google Maps Platformの利用規約に従い、必要な項目のみをリクエストし、地図コンテンツには所定の帰属表示を行う。
- 外部由来の詳細情報は永続化せず、場所IDを用いて必要時に取得する。営業時間・評価は初回範囲に含めない。

### 実装設計
- フロントエンドの場所検索画面で、検索語、カテゴリ、地域／現在地の選択、検索半径を入力する。現在地の取得は検索操作に伴う明示的なボタン操作時だけ実施する。
- 認証済みメンバーのみが利用できる既存の`/api/places` Route Handlerを拡張する。サーバー側で入力値を検証し、既存どおりログイン状態とグループ所属を確認してからGoogle APIを呼び出す。
- 地域入力はGeocoding APIを1回呼び出して中心座標を取得し、その後Places Text Searchを呼び出す。現在地モードではクライアントから渡された緯度・経度を範囲検証して使う。
- Text Searchは`locationBias.circle`、`languageCode: "ja"`、`regionCode: "JP"`、`pageSize: 20`を指定する。`maxResultCount`は使用しない。お店・飲食店・カフェでは3種類の検索を実行し、駐車場では1種類の検索を実行する。各検索の失敗を隠さず、いずれかが失敗した場合は検索全体をエラーとして返す。
- FieldMaskはPlace ID・名称・住所・位置座標に限定する。Places検索結果はPlace IDで重複排除し、Haversine距離で半径内に絞り、距離順で最大10件を返す。
- Google Maps APIキーはサーバー環境変数でのみ使用し、Places API (New)とGeocoding APIを有効化して、キーのAPI制限に両方を追加する。
- 検索結果の距離は「直線距離」と明示する。経路距離はRoutes APIを導入するため初回範囲に含めない。

### 費用・利用条件
- 現在地検索はGeocoding APIを呼び出さない。地域入力検索ではGeocoding APIを検索ごとに1回呼び出す。
- 「お店・飲食店・カフェ」はPlaces Text Searchを1検索あたり最大3回、「駐車場」は最大1回呼び出す。いずれもPlaces Text Search Proの対象となり得る。Google Maps Platformの無料利用枠を超えると課金される可能性があり、無料枠は課金停止の上限ではない。
- 調査時点のグローバル料金表ではGeocodingは月10,000回まで無料、その後の最初の料金帯は1,000回あたりUS$5。Places Text Search Proは月5,000回まで無料、その後の最初の料金帯は1,000回あたりUS$32。料金は請求先アカウント・地域・最新の料金表に従う。

### 初回実装の範囲
- キーワード、カテゴリ、地域または現在地、半径指定、直線距離表示、お気に入り登録を実装する。
- 地図上での候補表示自体はFR-007で扱う。営業時間・評価・駐車料金・空き状況は初回範囲に含めない。
- Google APIキーの設定と実リクエスト確認は利用者側でキー設定後に行う。
